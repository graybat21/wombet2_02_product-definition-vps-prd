`SRS_v0.3_by_gemini.md` 문서와 기존 `01_TASK_리스트_추출_결과.md`를 교차 검증한 결과, UI 영역 외에도 **MVP 운영과 외부 유입(SEO/B2B)을 위해 반드시 필요하지만 누락된 백엔드/데이터 파이프라인 태스크** 4가지를 추가로 도출했습니다.

## 누락 사유 및 검토 내용 (Context)

1. **관리자(Admin) 개입 파이프라인 부재 (ADM-001)**
   * **문제**: 사용자가 발 사진을 올리는 API(`F2-001`)와 결과 조회 API(`F2-002`)는 있지만, 관리자가 그 사이에서 2시간 내에 진단 결과를 시스템에 **'업로드'**하는 창구가 없습니다. (SRS 6.3 시퀀스 3에 명시된 `Admin->>Backend` 과정 누락)
   * **보완**: 최소한 백오피스에서 진단 세션 ID를 기반으로 히트맵 JSON을 PATCH 할 수 있는 내부용 API가 필요합니다. 또한 단점 DB 전문가 검증 후 Publish 하는 API도 필요합니다.

2. **초기 구동 데이터 부재 (DAT-001)**
   * **문제**: 테이블 생성(DB-001~003)만 정의되어 있고, SRS 1.2 Scope에 명시된 "수동 DB 30~50종"을 실제 환경(Dev/Prod)에 주입하는 절차가 없습니다.
   * **보완**: 빈 화면을 띄우지 않기 위해, 환경 구축 시점에 데이터를 밀어넣는 Seeder 스크립트 작성이 필수입니다.

3. **오가닉 유입 기술 지원 부재 (SEO-001)**
   * **문제**: SRS 1.2 Scope에 "SEO 롱테일 콘텐츠"를 범위로 명시했으나, 이를 달성하기 위한 기술적 태스크가 없습니다.
   * **보완**: 검색 엔진 봇(Bot)이 제품 상세 페이지의 단점 정보를 긁어갈 수 있도록 SSR 기반의 메타태그 처리와 사이트맵 생성이 필요합니다.

4. **B2B 연동용 방어벽 부재 (INF-004)**
   * **문제**: F2-003에서 B2B용 검증 API(`/api/v1/fit/diagnosis`) 제공을 정의했으나, SRS 3.3 제약조건인 "호출 제한 10K건/월"을 통제할 인증/제한 장치가 없습니다.
   * **보완**: 파트너사별 API Key 발급 체계와 트래픽 초과를 막는 Rate Limiting 미들웨어를 추가해야 B2B 비즈니스가 안전하게 구동됩니다.
